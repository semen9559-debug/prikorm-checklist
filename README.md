# Мама рядом

PWA-спутник первого года: трекер прикорма, сумка в роддом, покупки, развитие по
месяцам, режим сна, дневник дня, документы и выплаты, календарь прививок,
подготовка к родам по неделям.

Работает без аккаунта — данные хранятся в браузере. Аккаунт нужен только для
семейной синхронизации: чтобы второй родитель видел те же отметки.

Прод: <https://prikorm.dverizapeli.ru> (GitHub Pages, ветка `main`).

## Запуск и проверки

```bash
npm install          # eslint + playwright (только для разработки)
npm run serve        # http://127.0.0.1:4173
npm run lint         # линтер: ищет реальные ошибки, а не стиль
npm test             # дымовые тесты в headless-браузере
npm run check        # синтаксис + линтер + тесты разом
```

`npm test` поднимает статический сервер, открывает приложение в Chromium и проверяет
28 вещей: страница не белая, все 10 разделов не пустые, отметка переживает
перезагрузку, модалка держит фокус и закрывается по Escape, тема меняет цвет
статус-бара, белый список ключей синхронизации и слияние данных работают, консоль
чистая. Скриншоты складываются в `tests/`.

## Релиз

Версия живёт в четырёх местах (`version.json`, `APP_VERSION`, `?v=` у css/js и
`VERSION` в `sw.js`) и правится одной командой:

```bash
npm run release        # v70 → v71
npm run release 85     # конкретный номер
git add -A && git commit -m "Release v71" && git push
```

CI на каждый push проверяет, что версия нигде не разъехалась.

## Синхронизация семьи

Что уезжает на сервер: отметки, реакции, даты, заметки, свои продукты, дети,
дневник, списки сумки и покупок, навыки, документы, прививки, беременность.

Что остаётся на устройстве: тема, открытый раздел, свёрнутые категории, выбранный
ребёнок, звук, состояние онбординга.

Как это устроено:

- запись в базу идёт **пачками с задержкой 700 мс** — без этого одна заметка
  превращалась в десятки запросов (по одному на нажатие клавиши);
- чужие правки применяются **точечно, без перезагрузки страницы** — приложение
  перечитывает хранилище по событию `family-sync` и перерисовывает текущий экран;
- при слиянии значения **объединяются**, а не затираются: одновременные отметки с
  двух телефонов не теряются (компромисс описан в `mergeValues`);
- своё же эхо распознаётся по совпадению значения, поэтому синхронизация работает и
  между двумя устройствами одного аккаунта.

## Настройка Supabase

1. Создайте проект и включите Email/Password authentication.
2. В **Auth → URL Configuration** добавьте `https://prikorm.dverizapeli.ru` в Site URL
   и Redirect URLs. Для локального теста — `http://127.0.0.1:4173`.
3. Выполните целиком [`supabase/schema.sql`](supabase/schema.sql) в SQL Editor.
   Файл идемпотентный: его же запускают при обновлении схемы.
4. Скопируйте Project URL и **publishable anon key** в
   [`scripts/supabase-config.js`](scripts/supabase-config.js).
   Никогда не добавляйте туда service_role key или пароль базы.
5. Зарегистрируйте два аккаунта, войдите первым, перенесите локальные данные и
   создайте приглашение в разделе «Аккаунт и семья».

Схема даёт участникам семьи доступ только к своим данным, позволяет владельцу убрать
участника и удалить данные семьи с сервера, ограничивает размер записи (200 КБ) и
число действующих приглашений (20).

Email-приглашение открывает подготовленное письмо в почтовом клиенте. Для
автоматической отправки нужен SMTP-провайдер или Supabase Edge Function.

## Клиент Supabase

`scripts/vendor/supabase.js` — заглушка, которая пока берёт клиент с CDN.
Чтобы убрать зависимость от стороннего хоста и плавающей версии:

```bash
npm run vendor       # скачает и зафиксирует версию в репозитории
```

## Структура

```
index.html            разметка всех разделов + мета, CSP, автообновление
privacy.html          политика конфиденциальности
scripts/app.js        данные разделов и вся логика интерфейса
scripts/family-auth.js  аккаунт, семья, синхронизация
scripts/vendor/       локальная копия клиента Supabase
styles/app.css        оформление
sw.js                 service worker (сеть → кэш, версия из релиза)
supabase/schema.sql   таблицы, политики RLS и функции
tools/                релиз, проверка версии, локальный сервер, вендоринг
tests/smoke.mjs       дымовые тесты
```
